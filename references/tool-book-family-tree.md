# Tool-Book Family Tree For AI Agent Strategy Work

Use this reference when a user has read business, strategy, consulting, or
presentation tool books and wants to turn those learnings into AI-agent skill
behavior. This is a synthesis protocol, not a book-summary archive.

## Source Boundary

- Default source label: `user-provided reading notes`.
- If the user gives only titles or highlights, treat the output as an original
  digest of those notes plus public metadata, not as a definitive full-book
  summary.
- Do not copy passages, chapter structures, proprietary cases, distinctive
  tables, diagrams, or third-party online summaries.
- Do not imply endorsement by authors, publishers, consulting firms, platforms,
  or book retailers.
- Keep all public repo wording original and compatible with the CC BY 4.0
  content license.

## Family Tree

```text
Tool-book learning for AI agents
├─ Strategic lens family
│  ├─ Sunzi for managers: terrain, opponent, timing, restraint
│  ├─ Sunzi for executives: leadership judgment, command clarity, execution discipline
│  └─ Business-war cases: rivalry patterns, sequencing, second-order moves
├─ Consulting diagnosis family
│  ├─ MECE / logic tree: decompose the question before recommending
│  ├─ 3C: customer, company, competitor fit
│  ├─ Porter Five Forces: industry structure and profit-pool pressure
│  └─ SWOT: synthesize after evidence, not before evidence
├─ Advantage / portfolio family
│  ├─ Where-to-play: choose market, segment, channel, workflow, or use case
│  ├─ How-to-win: define advantage, tradeoff, capability system, and moat hypothesis
│  └─ Investment tier: scale, test, partner, pause, or kill
├─ Operating system family
│  ├─ PDCA / PDSA: plan, test, check, adjust
│  ├─ SOP / RACI: owner, backup, exception, rollback, audit log
│  └─ Metrics / kill criteria: leading signal, guardrail, stop rule
└─ Presentation family
   ├─ One-slide storyline: decision, tension, evidence, move, risk, stop rule
   ├─ Pyramid / top-down answer: answer first, support second
   ├─ Data-storytelling: show the proof signal, not every datum
   └─ Executive deck review: cut jargon, sharpen tradeoff, name next decision
```

## Reader Digest Contract

When converting user-read books into AI-agent material, produce:

1. `Reader Digest`: 5 to 9 original reader digest bullets that compress the
   user's notes into business-useful ideas.
2. `Tool Family Placement`: where each idea belongs in the family tree.
3. `AI-Agent Behavior`: the instruction, prompt gate, review rubric, or output
   section the idea should change.
4. `Evidence Needed`: what artifact, metric, observation, or source would make
   the idea decision-grade.
5. `Misuse Risk`: how the idea could become framework theater, manipulation, or
   unsupported advice.
6. `Presentation Angle`: the one-slide message a consultant could defend.
7. `Operating Cadence`: owner, decision rule, review rhythm, adoption telemetry,
   customer economics signal, and stop / adjust trigger.
8. `Advantage / Portfolio Choice`: where-to-play, how-to-win, capability system,
   tradeoff, investment tier, and scale / kill rule.

Do not output a chapter-by-chapter book report. Do not treat a book title as
proof. The digest must change a decision, method selection, evidence requirement,
metric, or stop rule.

## MECE Issue-Tree Contract

Run this before method selection when the user's reading notes are being turned
into an AI-agent workflow.

| Element | Requirement |
|---|---|
| Root question | State the decision or agent behavior being improved. |
| Branches | Use mutually exclusive branches that do not duplicate the same cause or method. |
| Coverage | Make the tree collectively exhaustive enough to cover strategy, diagnosis, operation, presentation, and evaluation. |
| Evidence / falsifier | Each branch needs evidence, missing data, and what would falsify it. |
| Decision impact | Each branch must change an instruction, output section, metric, or stop rule. |
| Unknown lane | Keep an explicit unknown / missing-data branch instead of hiding uncertainty. |

## AI Agent Operating Cadence

Use this cadence when book learning is meant to change real AI-agent behavior.

| Step | Agent behavior | Required output |
|---|---|---|
| Intake | Capture decision, user-provided notes, target workflow, customer economics lever, and source label. | Decision, source label, customer value lever, owner. |
| Diagnose | Run method screen, family placement, terrain map, and Sunzi lens only after evidence. | Family placement, evidence ledger, selected method, selected lens. |
| Decide | Return `go / revise / stop` with accountable owner and decision rule. | Verdict, owner, decision rule, competing diagnosis. |
| Operate | Set the weekly metric review, source of truth, escalation path, and adoption telemetry. | Weekly cadence, metric, adoption signal, escalation rule. |
| Learn | State what the agent changes next cycle based on evidence. | Learning rule, stop / adjust trigger, next prompt or workflow change. |

## Customer Economics Scorecard

Use this scorecard when the reader digest affects growth, ecommerce, pricing,
product adoption, or operating model decisions.

| Area | Evidence to request | Why it matters |
|---|---|---|
| Customer value | Activation, repeat use, completion rate, willingness-to-pay signal, retention proxy. | Proves the method changes customer behavior, not just messaging. |
| Unit economics | Contribution margin, CAC / payback impact, refund rate, support cost, inventory opportunity cost. | Prevents growth advice that wins traffic but loses profit. |
| Adoption telemetry | Weekly active workflow, task completion, handoff count, user override rate, time to value. | Shows whether the AI agent is becoming an operating habit. |
| Risk guardrail | Complaint rate, escalation count, compliance issue, trust signal, error recurrence. | Catches harm before scale. |
| Decision rule | Threshold for go, revise, stop, wait, or retreat. | Turns book learning into accountable action. |

## AI-Agent Application Plan

1. Intake: capture titles, user highlights, context, target AI-agent behavior,
   and whether notes are user-provided or public metadata only.
2. Distill: turn the notes into reader digest bullets and place each bullet in
   the family tree.
3. Translate: convert each learning into skill instructions, review gates,
   evidence requirements, templates, or examples.
4. Simulate: run the synthetic consultancy panel and preserve dissent.
5. Validate: require evidence ledger, method fit, advantage / portfolio choice,
   safe-source label, one-slide headline, customer economics scorecard,
   operating cadence, adoption telemetry, metrics, and kill criteria.
6. Apply: route the final behavior into `sunzi-strategy-consultant`,
   `sunzi-terrain`, the domain adapters, and
   `strategy-analyst-review`.

## Acceptance Criteria

- The output says what it changes in the AI agent.
- The output has a family-tree placement, not a loose reading list.
- The output includes a MECE issue-tree contract before method selection when
  the user wants deep book-learning application.
- Every method is evidence-gated.
- Advantage / portfolio choices name where-to-play, how-to-win, capability
  system, tradeoff, investment tier, and scale / kill rule.
- Every operating recommendation has owner, cadence, decision rule, adoption
  telemetry, customer economics signal, and stop / adjust trigger.
- The panel review is labeled synthetic.
- No copied copyrighted book content appears.
- The final recommendation includes a stop / retreat trigger.
